Approve: build albums and sharing in seven checked steps, with one builder and one reviewer

The album operations come first, because the picker, the viewer and the swipe deck all call them.

What changes

+
Create an album, add a photo, remove a photo and export the original, in the photo library and in the test fake. Unit tests on the fake check each one. PhotoLibrary
+
The model looks up albums and writes to them. It clears a pending delete when a photo joins a protected album, and it keeps the last 3 albums used. Unit tests cover the rule and the recent list. AppModel
+
The album picker sheet with New album, search, Recent and every album, check marks and "Not protected". Screenshots in light and dark.
+
Album and Share in the viewer's top bar, and an Album round button in the swipe deck.
+
Sharing exports the file first, with a Cancel button on the spinner, then opens the system share sheet. The file is removed when the sheet closes. Checked by sharing a sample photo to Files on the simulator.
+
A UI test that adds the top card to a new album from the deck. Then the full clean test run on the iOS 26.4 simulator.
=
A fresh reviewer, then an install on your iPhone.

Risk → answer

An album write lands in the wrong album, or a delete stays queued.
A fresh reviewer checks every album write and the delete queue rule. Unit tests pin the rule.
The picker or a button is built before the calls it needs.
Steps 1 and 2 come first, and each ends in passing tests.
Sharing breaks with no test to catch it.
Step 5 shares a sample photo to Files on the simulator and checks the share sheet.
