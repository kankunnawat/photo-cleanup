Approve: one builder makes the app in eight checked steps, then a fresh reviewer checks the delete path

Every step ends with its check and a commit, and the app goes on your iPhone only after the review.

What changes

+
An Xcode project generated from one file, with the app, unit tests and UI tests. Your team ID stays in a local file that git ignores. project.yml Config/Local.xcconfig
+
The core logic with unit tests: pending decisions with undo, the protected set, Free up space candidates, screenshot and video buckets, and the apply order.
+
The link to the Photos library: find or create the Keep album, thumbnails, sizes, add to album, delete, and a refresh when the library changes.
+
The screens: permission gate, Home, Swipe review, Free up space, Screenshots, Large videos, Apply, Settings and the iCloud notice.
+
A size cache that fills in the background and feeds the totals.
+
A UI test on the iOS 26.4 simulator: sample photos, one swipe each way, Apply, and accept the iOS delete alert.
+
A fresh review of the delete path and the protected set, then an install on your iPhone. xcrun devicectl
=
Your photo library: every test runs on the simulator with sample photos.

Risk → answer

A bug in the delete path removes a photo you keep.
A reviewer who did not write the code reads the delete path and the protected set before the install. Unit tests cover the protection check before apply.
Your team ID ends up in git.
It sits in a local settings file that git ignores, and the generated Xcode project is ignored too.
The iOS delete alert stops the UI test.
The test accepts the alert itself, and photo access is granted before the run. xcrun simctl privacy
